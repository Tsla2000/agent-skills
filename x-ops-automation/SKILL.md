# X 账号自动化运营 Skill

> 来源：真实运行中的系统（2026-10-11 上线，账号 @PRO_AI_99T）。发帖数量不设上限，人工只负责确认和验收。

## 核心理念

Agent 负责重复执行，规则负责约束行为，人负责方向、关键决策和结果验收。

## 一、四层架构

```
规则层：Markdown 文件
    定义选题、写作、风控、回复和验收标准
              ↓
调度层：定时任务
    按计划触发不同运营任务
              ↓
执行层：AI Agent + 浏览器
    收集信息、生成草稿、执行获准的操作
              ↓
状态层：state.json + 每日日志
    记录运行状态、执行结果、异常和熔断状态
```

## 二、写作规则

- 长度：100–140 中文字符，280 加权字符以内
- 钩子开头：第一句必须是数字、反差或结论，不许"大家好"式开场
- 一句一件事，给数不给形容词，不说废话
- 不编造：数字必须来自信息源；不确定的标注"据报道"
- 不给直接交易建议，只呈现信息和判断框架
- 每天多帖角度必须不同；一周内不重复同一信源

### 钩子八选一

灾难体 / 快讯体 / 暴论体 / 吃瓜体 / 数据炸弹 / 时间反差 / 名人打脸 / 身份反差

### 发帖前检查清单（6 项缺一不可）

1. 信源链接真实可打开
2. 数字与信源一致
3. 字数符合要求
4. 角度与今日另一帖不同
5. 无 AI 味套话
6. 日志已记录

## 三、选题标准

- 只选过去 24 小时内的真事：数据、财报、评级变动、政策、产品发布
- 优先级：与关注领域相关的 > 行业基础设施 > 宏观
- 避开：未经证实的小道消息、纯情绪帖、重复昨天已发过的角度

## 四、定时任务清单

| 任务 | 频率 | 职责 |
|---|---|---|
| 午间草稿 | 每天 12:15 | 生成午间内容草稿 |
| 晚间草稿 | 每天 21:00 | 生成晚间内容草稿 |
| 评论巡查 | 每天 21:30 | 整理新评论，生成候选回复 |
| 突发监控 | 每小时 | 重要事件才打断人，平时静默 |
| 粉丝日报 | 每天 08:18 | 记录粉丝数，算增速 |

冷启动建议：先只开午间+晚间两个草稿任务，跑顺了再加。

## 五、发布流程（人类保留最后确认权）

```
定时任务触发 → 检查熔断状态 → 读规则+当日记录
→ 抓取信息生成草稿 → 跑 6 项检查清单
→ 草稿发人确认（全文+选题一句话+信源+为什么选这个角度）
→ 人确认后发布 → 核对结果 → 记日志 → 更新状态
```

## 六、风控红线

- X 禁止非 API 自动化操作（封号风险）：没有合规接口就保留人工发布
- 评论自动回复需 X 书面批准：只做"整理+候选回复"，不自动发送
- 每条文案必须唯一；不要把算法猜测当确定规律
- 熔断开关：状态异常时直接暂停所有任务，先停再查

## 七、三个真实踩坑

1. **数据口径误报**：第一次抓粉丝数报了 9.3 万，实际 29 个。每个数据源先手动验证采集口径再自动化。
2. **假设当规律**：公开的算法代码不等于线上实现。规则分三级——平台规则 / 可验证经验 / 待验证假设，假设永不进执行链。
3. **为全自动赌账号**：浏览器自动发布技术可行但违规。技术可行 ≠ 合规。

## 八、从零搭建顺序

1. 账号定位、目标、内容边界写下来
2. 建工作区，写规则文件
3. 信息源逐个验证
4. 先跑单任务草稿生成，人工发布验证质量
5. 质量稳定后加定时调度
6. 加数据追踪、评论整理、突发监控
7. 加状态机、重试上限、熔断

总原则：先证明每个环节可靠，再把它们连起来。
